# Firmware build stages

Each stage builds on the previous one. Load any `sketch.ino` into
[Wokwi](https://wokwi.com) (new project → search "STM32 Blue Pill"),
wire per `wokwi_config/diagram.json`, and run.

## stage0_baseline
Timer-driven ADC sampling at a fixed baseline rate, printed over serial.
Confirms the signal path works before adding any detection logic.
Reads from a potentiometer (stand-in for a real voltage-sensing front end).

## stage1_waveform_injection
Replaces the potentiometer read with playback of a precomputed synthetic
IEEE-1159-style waveform (`waveform_table.h`, generated by
`../../analysis/generate_waveform.py`), containing a labeled sag and swell.

## stage2_trigger_detector
Adds the trigger detector: a slope test and an RMS-deviation test, combined
with OR. Detects and logs triggers but does not yet change sample rate or
manage a capture buffer.

## stage3_full_fsm
The complete two-state FSM: BASELINE and TRIGGERED states, pre-trigger ring
buffer, capture buffer, hysteresis-based return to BASELINE. This is TASA
as described in the paper. Produces the `RAW_stage3_firmware_log.txt` data
in `../../data/`.

## Known simulator quirks (see paper Section VII for full limitations list)
- Wokwi's simulated STM32 ADC returns 10-bit values (0-1023), not the real
  hardware's 12-bit range (0-4095).
- STM32F103 (Blue Pill) was used instead of the intended STM32L4 deployment
  target, due to Wokwi's simulator support at the time of writing.
